Performance Lab/ Experiment #001, opened October 2026

Typed events: the elegant type that slowed down every call site

Does a mapped type with an as clause, indexed at every call site, make type-checking measurably slower than inferring the event name from a generic parameter?

See the resultsReproduce it
Lab #001Confirmed−57%check time with TypeScript 7 after the fixComputed from medians, Nov 9, 2026. Verified on TypeScript 6.0.3 and TypeScript 7.0.2.

Verdict

Yes. On an Apple M3 Pro (12 cores), inferring the event name from the generic parameter cut check time by 52% with TypeScript 6 and by 57% with TypeScript 7 (51% to 65% from the fastest and slowest runs); on a 1-core Intel Xeon, by 41% and 65%. The safety check passed on both machines, so the type safety is the same. Narrowing include to src also stopped TypeScript from reading a generated file the app never imports.

Takeaway

A mapped type with an as clause is evaluated backwards at each indexed call site. If you can infer the key from a generic instead, the checker does far less work.

Note Both machines use the earlier protocol: 3 runs per condition, no warm-up, runs in sequence. On the Apple M3 Pro, the runs of TypeScript 7 after the fix vary more than the others (0.117 s to 0.159 s, 15.2% coefficient of variation), hence the wider range on that figure.

Note The two machines differ by CPU as well as core count: compare the before and after conditions within a machine.
